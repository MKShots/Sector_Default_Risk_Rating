# Sector-Level Credit Risk Framework for HKEX Equities

A reproducible Python pipeline that estimates **sector-level credit risk** for companies listed on the Hong Kong Stock Exchange (HKEX) using a **Merton structural default model**.

The framework builds the HKEX equity universe from the official securities list, enriches each company with market and balance-sheet data from Yahoo Finance, and estimates **Distance-to-Default (DD)** and **Probability of Default (PD)** at the sector level — reported alongside market-cap coverage metrics and two complementary aggregation approaches.

---

## Key Features

- **Universe construction** directly from the official HKEX List of Securities.
- **Automated data collection** via Yahoo Finance (sector, market cap, price history, balance-sheet debt).
- **Transparent eligibility rules** — companies are included only when market cap, debt, and sufficient price history are all present.
- **Coverage metrics** so each sector's estimate can be judged for reliability.
- **Two PD methodologies side by side:**
  1. **Input-aggregated PD** — treats the whole sector as one consolidated firm.
  2. **Value-weighted PD** — computes each company's PD first, then weights by market cap.
- Fully **relative paths** and **regenerable outputs** for clean reproducibility.

---

## Why Two PD Methods?

Merton PD is a **nonlinear** function of leverage and volatility, so by Jensen's inequality the PD of aggregated inputs is *not* the same as the aggregate of company PDs.

- **Input-aggregated PD** answers: *"If the entire sector were one merged balance sheet, what is its PD?"* This method can bury a small, highly-levered firm inside a large, safe one — understating tail risk.
- **Value-weighted PD** answers: *"What is the market-cap-weighted average of each firm's own default risk?"* This keeps levered constituents out in the convex tail where they belong.

A large gap between the two columns is itself a signal: it flags **hidden leverage dispersion** within a sector.

## Methodology

The Merton (1974) model treats equity as a call option on the firm's assets.

Distance-to-Default:

```
DD = [ln(V / D) + (r + 0.5 * sigma^2) * T] / (sigma * sqrt(T))
```

Probability of Default:

```
PD = N(-DD)
```

where `V` = asset value, `D` = debt, `r` = risk-free rate, `sigma` = asset volatility, `T` = time horizon (1 year), and `N()` is the standard normal CDF.

**Sector adaptation:** for each sector, equity value and debt are summed across Merton-eligible companies, and equity volatility is estimated from a market-cap-weighted daily sector return series. The two-equation Merton system is then solved for asset value and asset volatility.

## Workflow / Run Order

The notebook is designed to run **top to bottom**. Phases must run in order because later steps depend on earlier variables.

1. **Phase 1 — Workbook setup:** environment, package install, imports, settings, and output folders.
2. **Phase 2 — Universe construction:** download HKEX securities list, filter to equities, build Yahoo-compatible tickers.
3. **Phase 3 — Unified extraction:** one function per company returning sector, market cap, debt, and price history.
4. **Phase 4 — Eligibility & sector inputs:** classify Merton-eligible firms, compute coverage, build sector returns and volatility.
5. **Phase 5 — Merton solve:** risk-free rate, per-company PD (value-weighted view), and sector-level Merton solve (input-aggregated view).
6. **Phase 6 — Summary report:** final per-sector table with both PD columns, coverage, and risk bands.

## Limitations

- Merton PD levels are **relative indicators**, not calibrated real-world default frequencies.
- Sector volatility from a market-cap-weighted portfolio embeds diversification, which can suppress the input-aggregated PD (see *Why Two PD Methods?*).
- Coverage below ~80% means a sector's estimate rests on a partial sample — interpret with care.
- Data quality depends on Yahoo Finance availability; missing debt or short price history excludes a company.
